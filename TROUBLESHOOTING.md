# Troubleshooting — getting a server actually running

Everything here is baked into [`agent/setup_arena.sh`](agent/setup_arena.sh),
the one-command bootstrap. This doc explains *why* each step exists, so you
can debug if something drifts. These are real gotchas hit on macOS with
OpenTTD 15.3.

## TL;DR

```bash
git clone https://github.com/walter-grace/agent-openttd-arena
cd agent-openttd-arena
./agent/setup_arena.sh
```

That installs OpenTTD if needed, downloads base graphics, installs the AI +
GameScript, writes a correct config, and starts a dedicated server with the
admin port open. Then `open -a OpenTTD` → Multiplayer → join `127.0.0.1`.

## The gotchas, and the fixes

### 1. `brew install --cask openttd` ships NO base graphics
The game installs, but it can't generate a map — you'll see
`original_dos: (unusable: 5 missing files)` and the dedicated server logs
`Network online` then **never opens its ports**. OpenTTD normally downloads
OpenGFX on first GUI launch, but a headless server can't.
**Fix:** download OpenGFX into `~/Documents/OpenTTD/baseset/`:
```bash
curl -sL -o /tmp/g.zip https://cdn.openttd.org/opengfx-releases/7.1/opengfx-7.1-all.zip
unzip -oq /tmp/g.zip -d /tmp/g && tar -xf /tmp/g/opengfx-*.tar -C ~/Documents/OpenTTD/baseset/
```

### 2. OpenTTD 15.x disables password admin login by default
`admin_client.py` (and thus the whole MCP layer) authenticates to the admin
port with a password. In 15.x, `network.allow_insecure_admin_login` defaults
to **false**, so the admin port **won't even open** for password auth — port
3977 stays closed no matter what password you set.
**Fix** in `openttd.cfg`:
```ini
[network]
admin_password = nutzarena
server_admin_port = 3977
allow_insecure_admin_login = true
```

### 3. A dedicated server needs `-g` to start a game
`openttd -D` alone initializes networking but may sit without a world, so
neither the game port (3979) nor admin port (3977) opens. `-g` (with no
argument) starts a new random game immediately; `-g <heightmap.png>` loads a
real-world scenario.

### 4. AIs and GameScripts load from config *slot lines*
`[ai_players]` and `[game_scripts]` are lists of slots, one per line, where
`none =` is an empty slot. To load content, replace a `none` with the
script's **`GetName()`**:
```ini
[ai_players]
Nutz Executor =     ; must match info.nut GetName() exactly

[game_scripts]
Nutz Bridge: arena =    ; the GS generated by bridge_gs.py
```
Also set `[ai] ai_in_multiplayer = true` and `[difficulty]
max_no_competitors = 4` so AIs actually spawn.

### 5. The GameScript must be generated first
The bridge GS isn't a static file — `agent/sandbox/bridge_gs.py` generates
`~/Documents/OpenTTD/game/nutz_bridge_<name>/` (state push + blueprint
mailbox). `setup_arena.sh` does this with an empty town list (bare bridge);
use `build_scenario.py` for a real-world map with founded towns.

### 6. "The agents aren't building anything"
An AI company spawning ≠ agents building routes. The **Nutz Executor is an
executor**: it builds *blueprints* handed to it via the bridge GS's sign
mailbox. To generate that activity, run the **conductor**, which picks towns
and dispatches blueprints:
```bash
python3 -u -m agent.sandbox.conductor --interval 30 --intra-town
```
Without it (or an external agent calling `dispatch_route`), the executor
idles and slowly funds towns.

### 7. macOS blocks writing to `~/Documents` from some shells
If a script or automated process gets `Operation not permitted` writing to
`~/Documents/OpenTTD`, that's macOS TCC (privacy) protection. Run
`setup_arena.sh` from **your own Terminal** (which has Documents access), not
from a sandboxed/automated context. Or set `OTTD_DIR` to a path outside
`~/Documents`.

### 8. Can't see console output / rcon replies over a pipe
Driving the dedicated server's console via a FIFO works for the game, but
capturing replies is flaky when the process is detached. For interactive
control, run the server in a terminal you can see, or use the admin port
(`admin_client.py`) which is the intended programmatic interface.

## Verifying it worked

```bash
# ports open?
nc -z 127.0.0.1 3979 && echo "game port up"
nc -z 127.0.0.1 3977 && echo "admin port up"

# admin layer connects?
python3 -c "import sys;sys.path.insert(0,'agent');from admin_client import OpenTTDAdminClient as C;c=C(password='nutzarena');c.connect();print('admin OK');c.close()"

# then: open -a OpenTTD → Multiplayer → Search LAN → join your server name
```
